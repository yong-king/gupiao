# 28 高提醒企业微信/微信投递计划

状态：spec_ready

## 目标

为 PC 端项目增加“高提醒外部投递”能力，把提醒中心中的 `high` 和 `critical` 提醒发送到企业微信，或为后续微信相关通道接入预留统一抽象，并在控制台中提供配置、测试和结果查看能力。

## 范围

- 新增高提醒外部投递规范与计划。
- 设计高提醒筛选、去重、冷却与投递日志模型。
- 设计企业微信通道优先实现方案。
- 设计 MCP 接入边界与统一调用层。
- 设计 PC 端配置页、测试发送和投递记录展示。
- 设计配置文件与敏感信息注入方式。

## 非目标

- 不在本计划内实现移动端推送。
- 不在本计划内承诺个人微信自动化直发。
- 不在本计划内实现邮件、短信、电话等多通道体系。
- 不实现自动交易通知。

## 任务

- [ ] 设计高提醒外部投递的数据结构与状态流转。
- [ ] 设计企业微信通道配置与发送抽象。
- [ ] 设计 MCP 通道执行器接入边界。

- [ ] 设计 PC 端配置入口、测试消息和投递日志页面。
- [ ] 设计配置文件、环境变量和敏感信息管理方式。
- [ ] 设计测试方案与冒烟验证流程。
- [ ] 完成后提交实现代码与文档。

## 测试门槛

- Go：高提醒筛选、去重、冷却、通道适配层测试通过。
- 前端：配置页、投递记录、状态展示测试通过。
- MCP：如果接入 MCP，至少有一条成功调用和一条失败回写的冒烟验证。
- 企业微信：测试消息发送成功。
- 原有提醒中心回归通过，不受外部投递失败影响。

## 完成标准

- 高提醒可外发到企业微信。
- 微信能力边界清晰，不采用不合规方案。
- 控制台可配置、可测试、可查看发送结果。
- 投递链路可审计、可回溯、可失败回写。

## 交付说明

- 第一阶段优先实现企业微信通道。
- 微信相关能力只在合规、可审计的前提下扩展。
- MCP 只作为通道执行层，不替代项目内业务判断和审计。
